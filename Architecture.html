ARCHITECTURE.md

Stage 1 Proof of Concept (POC)

Human-in-the-Loop Multi-Agent Framework for Prospective LCA Assumption Development

1. Purpose

This repository implements the Stage 1 Proof of Concept (POC) of a human-in-the-loop multi-agent framework for prospective Life Cycle Assessment (LCA).

The objective of Stage 1 is not to generate a complete foreground Life Cycle Inventory (LCI).

Instead, Stage 1 assists LCA practitioners in developing scientifically justified process and inventory assumptions that can subsequently be reviewed by experts before engineering calculations are performed.

The framework currently terminates by producing a structured review package for expert review.

2. Scope

Included

  • Technology understanding
  • Process assumption development
  • Target-scale foreground inventory assumption development
  • Estimation method recommendation
  • Scientific review of assumptions
  • Structured review package generation

Excluded (Future Stage)

  • Human feedback integration
  • Engineering calculations
  • Foreground LCI generation
  • Material balance validation
  • Energy balance validation
  • Unit consistency validation
  • Background database integration

Why multiple representations?

Different representations are used because they serve different purposes.

Representation Purpose
technology.yaml User-provided case description and workflow input.
Pydantic models Strongly typed in-memory representation used for validation and LangGraph state management.
LLM JSON Communication protocol between the LLM and the application. The LLM is instructed to generate structured JSON matching predefined schemas.
Pydantic validation Ensures every LLM response conforms to the expected schema before being accepted. Invalid outputs fail immediately rather than propagating through the workflow.
review_package.yaml Canonical structured working format exchanged between agents and persisted by the framework.
review_package.xlsx Human-readable review interface for domain experts.

Design rationale

The framework intentionally follows the pipeline

LLM
    ↓
Structured JSON
    ↓
Pydantic Validation
    ↓
YAML
    ↓
Excel

rather than allowing agents to exchange free-text responses.

This design provides several benefits:

  • Enforces a fixed schema for every agent output.
  • Prevents inconsistent field names or missing information.
  • Detects malformed outputs immediately through schema validation.
  • Ensures downstream agents always receive valid structured data.
  • Separates reasoning (structured data) from presentation (Excel).
  • Improves auditability, reproducibility, robustness, and extensibility.

5. Design Philosophy

The framework follows four principles.

Human-in-the-loop

The framework assists experts rather than replacing them.

Final engineering decisions remain under expert control.

Structured reasoning

Agents communicate using structured schemas instead of free-text outputs.

Intermediate outputs should be machine-readable and auditable.

Modular architecture

Each component has a single responsibility.

Reasoning, orchestration, skills, schemas and tools remain independent.

Extensibility

Stage 2 should be implementable without redesigning Stage 1.

6. Stage 1 Components

Process Evolution Agent

Responsibilities

  • Interpret laboratory-scale processes
  • Recommend target-scale process assumptions
  • Recommend target-scale foreground inventory assumptions
  • Recommend estimation methods
  • Explain engineering rationale
  • Cite supporting evidence
  • Declare reasoning mode

Output

review_package.yaml (draft)

Scientific Review Agent

Responsibilities

  • Review process assumptions
  • Review inventory assumptions
  • Assess completeness
  • Assess plausibility
  • Assess justification
  • Assess traceability
  • Assess transparency
  • Assess uncertainty communication
  • Recommend revisions

The Scientific Review Agent evaluates whether assumptions are sufficiently justified for prospective LCA.

It does not determine whether an assumption is "correct".

Output

review_package.yaml (reviewed)

Orchestrator (LangGraph)

Responsibilities

  • Load user inputs
  • Load shared skills
  • Maintain workflow state
  • Execute agents
  • Pass structured outputs between agents
  • Invoke shared tools
  • Coordinate Stage 1 execution

The orchestrator currently does not invoke the review package export utility.

7. Shared Skills

Skills provide reusable reasoning guidance shared across multiple agents.

Current skills include:

  • review_specification.yaml
  • source_priority.yaml
  • engineering_heuristics.yaml
  • estimation_methods.yaml
  • process_evolution_examples.yaml

Skills influence reasoning but do not execute deterministic operations.

8. Shared Tools

Tools perform deterministic operations and contain no reasoning.

Current tools

  • YAML loader
  • Output writer
  • Logging

Standalone utilities

  • Review package export (review_package.yaml → review_package.xlsx)

The export utility is currently intended for development and validation and is executed manually.

Future versions will allow the orchestrator to invoke the export utility automatically.

Future tools

  • Review package import (review_package.xlsx → review_package.yaml)
  • Literature retrieval
  • Engineering calculations
  • Material balance validation
  • Energy balance validation
  • Unit consistency validation

9. Evidence Hierarchy

When multiple evidence sources are available, agents should prioritise them in the following order.

  1. User-provided documents
  2. Built-in engineering knowledge and provided reference materials
  3. Peer-reviewed literature
  4. Technical reports and standards
  5. Similar technology analogy
  6. General web resources
  7. LLM internal knowledge

Higher-priority evidence should always be preferred whenever available.

10. Reasoning Modes

Every assumption should explicitly state how it was derived.

Supported reasoning modes include:

  • Direct evidence
  • Engineering heuristic
  • Similar technology analogy
  • Literature synthesis
  • Engineering judgement
  • Conservative assumption

Reasoning mode should always be transparent.

11. Human Review Package

The final deliverable of Stage 1 is a single editable review workbook generated from the reviewed review_package.yaml.

Each process assumption is immediately followed by its associated inventory assumptions so reviewers can evaluate them together.

Suggested columns include:

  • Laboratory process
  • Proposed target-scale process assumption
  • Inventory flow
  • Type (Input / Output)
  • Recommended estimation method
  • Engineering rationale
  • Supporting evidence
  • Reasoning mode
  • Scientific review findings
  • Expert revision
  • Expert comments

Future versions will allow the revised workbook to be imported back into the framework.

Each folder has a single responsibility.

  • agents/ — reasoning agents.
  • orchestrator/ — LangGraph workflow orchestration.
  • prompts/ — prompt templates for reasoning agents.
  • skills/ — reusable engineering knowledge shared across agents.
  • schemas/ — YAML schemas exchanged between components.
  • models/ — Pydantic models used for validation.
  • tools/ — deterministic utilities.
  • state/ — shared LangGraph state.
  • tests/ — unit and integration tests.
  • cases/ — case-specific inputs, reference materials, execution artifacts, and generated review packages.

14. Development Principles

When implementing new functionality:

  • Prefer structured schemas over free-text communication.
  • Keep prompts focused on reasoning rather than storing knowledge.
  • Externalise reusable knowledge into shared skills.
  • Keep agents narrowly focused.
  • Keep the orchestrator lightweight.
  • Ensure every intermediate output is auditable.
  • Design components for future extension rather than one-off implementation.

15. Future Stage 2

Stage 2 will consume the expert-reviewed assumptions generated during Stage 1.

Planned components include:

  • Human expert review
  • Review Integration Agent (understands and incorporates expert revisions)
  • Review package import (Excel → YAML)
  • LCI Generation Agent
  • Engineering calculation tools
  • Material balance validation
  • Energy balance validation
  • Unit consistency validation
  • Foreground LCI generation

Stage 2 is intentionally outside the scope of the current proof of concept.
